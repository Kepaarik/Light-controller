# План Light Space

Light Space — новая версия LedHub: приложение на .NET 10 + WPF в трее, где подсветка каждой группы устройств сама переключается по запущенным приложениям. Код старого LedHub (папка `LedHub/` в корне репозитория) переносится по частям; сама папка `LedHub/` не меняется и не удаляется.

## Текущее состояние (ноябрь 2026)

План ниже — исходный. С тех пор направление изменилось:

- **Сценарии убраны** вместе со слежением за приложениями (условия «запущен» / «в фокусе», приоритеты, переходы). Вкладки «Сценарии» нет.
- **Режимы подсветки** (`SceneMode`): «Вся сцена», «Группы», «Устройства». Сейчас приложение при запуске всегда ставит «Устройства»: у каждого устройства своё содержимое и яркость (`AppConfig.DeviceLighting`).
- **Меню**: «Устройства», «Мониторы», список найденных устройств (каждое открывает свою страницу с выбором эффекта), внизу «Настройки». Меню сворачивается до значков. Страница «Сцена» в окно не подключена.
- **Типы содержимого в интерфейсе**: «Эффект» и «Музыка». Встроенные эффекты устройства — плитки над эффектами приложения во вкладке «Эффект» (в движке это по-прежнему отдельный тип `Builtin`); варианты одного эффекта — пресеты в боковой панели. «Сцена», «Экран», «Игра» в движке есть, но не выбираются; устройство, которое их играло, при запуске переходит на «Эффект».
- **Страница устройства**: галерея в основной части, настройки эффекта — в выезжающей панели справа; у неподключённого устройства настроек нет.
- **Диагностика**: вместо панели из плана — скрытый «Журнал устройств» в настройках (7 щелчков по заголовку), плюс счётчики вывода на странице «Устройства».
- **Мониторы**: лента привязывается к монитору, как в LedHub; ленту за монитором можно выбрать и на странице устройства.
- **Вывод**: неизменившийся кадр устройству повторно не отправляется; после сброса ELK перед запуском встроенного эффекта выдерживается пауза; BLE-ленты после подключения сначала получают команду включения; скорость встроенных эффектов ELK 0–100 % передаётся байтом не выше 0x74 — на большей скорости MELK-OA21 останавливает часть эффектов.
- **Окно**: закрытие завершает приложение, сворачивание прячет его в трей. Меню трея — «Открыть Light Space» и «Выход».
- Конфиг — версия 4.

Всё, что ниже относится к сценариям (условия, списки приоритетов, переходы, вкладка «Сценарии», этап 4), описывает исходный замысел и в текущем коде не реализовано.

## Решения

| Вопрос | Решение |
| --- | --- |
| Стек | .NET 10 + WPF |
| Подход | Новый проект, код из старого LedHub переносим по частям |
| Работа в фоне | Один процесс с иконкой в трее, подсветка работает при закрытом окне |
| Первая версия | Ленты и клавиатура, сцена со слоями, экран и музыка, игры |
| Сценарии | Устройства собраны в группы, у каждой группы свой список приоритетов; в группе играет один самый важный активный сценарий, без смешивания |
| Активация сценария | Настраивается в сценарии: процесс запущен или окно на переднем плане |
| Смена сценария | Плавный переход; снятие фокусного сценария с настраиваемой задержкой (по умолчанию 2 с), включение сразу |
| Новые устройства | Драйверы внутри проекта |
| Тесты и CI | Не делаем; проверка вручную через панель диагностики |
| Распространение | Только для себя |
| Оформление | Визуал LedHub: тёмное тонированное стекло (Acrylic или Mica) под всем окном, свои компоненты на общих токенах; стандартных элементов в стандартном виде нет |

## Модель данных

В каждой группе играет первый сценарий из её списка, у которого выполнено условие; если таких нет — «По умолчанию».

| Сущность | Что хранит |
| --- | --- |
| Устройство | Драйвер, возможности (адресное или нет, сколько светодиодов, как часто принимает кадры, есть ли встроенные эффекты), положение на сцене |
| Группа | Название, цвет обводки, набор устройств, яркость, упорядоченный список сценариев; внизу всегда «По умолчанию». Устройство входит ровно в одну группу; без группы оно само себе группа |
| Сценарий | Название, условие и содержимое. Один сценарий можно использовать в нескольких группах |
| Условие | exe-файл приложения + режим «запущен» или «в фокусе»; у «По умолчанию» условия нет |
| Содержимое | Одно из: эффект из галереи, сцена со слоями, экран, музыка, игра (Dota 2, CS2, другие), встроенный эффект устройства |

## Архитектура

Один поток кадров на всё приложение, у каждого устройства свой вывод, никаких общих изменяемых данных между потоками.

### Проекты

| Проект | Что в нём |
| --- | --- |
| LightSpace.Core | Цвета, геометрия сцены, модели конфигурации |
| LightSpace.Devices | Драйверы ELK/BLE, Robobloq, Tuya, RK S98 и остальные из старого `LedHub/Protocols` |
| LightSpace.Engine | Цикл кадров, рендер содержимого, выбор сценариев, слежение за приложениями |
| LightSpace.App | WPF: окно, трей, страницы, компоненты дизайн-системы |

### Потоки

1. **Поток кадров.** Один на приложение. Каждый кадр берёт неизменяемый снимок настроек и для каждой группы рендерит активный сценарий; во время перехода — два сценария и смешивает их.
2. **Вывод на устройство.** У каждого устройства почтовый ящик на один кадр: новый кадр заменяет неотправленный, поэтому медленный BLE не тормозит клавиатуру. Здесь же сглаживание клавиатуры и ограничение частоты (`MinFrameInterval`).
3. **Слежение за приложениями.** Запуск и закрытие процессов — WMI-события или опрос раз в секунду; смена окна в фокусе — `SetWinEventHook`. Наружу выдаёт только набор активных условий.
4. **Источники данных.** GSI-сервер игр, захват экрана и захват звука публикуют своё последнее состояние, рендер его только читает.
5. **UI.** Меняет конфигурацию — движок получает новый снимок. Обратно получает снимок цветов для живой сцены, не чаще 30 раз в секунду и только пока окно видно.

### Пространство

У каждого светодиода и клавиши есть координаты на сцене, эффект — функция «цвет(x, y, время)». На этом работают сцена, слои с границами, экран и полоски здоровья и маны на клавиатуре (здоровье — верхняя половина клавиатуры, мана/броня — нижняя).

### Конфиг и диагностика

- JSON в `%AppData%\LightSpace\config.json` с полем `Version` и миграциями при загрузке.
- Панель диагностики: время расчёта кадра; время отправки и число пропущенных кадров по каждому устройству; какой сценарий активен в каждой группе и почему.

## UX/UI: карта экранов

Главный экран — живая сцена с группами, слева меню из четырёх разделов: Сцена · Сценарии · Устройства · Настройки. В нешироком окне меню сворачивается до значков.

### Сцена (главный экран)

- Слева карта стола: устройства расставлены как в жизни и показывают живые цвета, которые сейчас уходят на железо. Пока окно скрыто, превью не рисуется.
- Группа создаётся на сцене: выделить устройства рамкой или Ctrl+кликом → «Сделать группой». Группа обведена своим цветом, с названием и активным сценарием.
- Справа панель выбранной группы: список сценариев с перетаскиванием, активный отмечен «▶ играет», внизу «По умолчанию»; кнопка «+ сценарий»; яркость группы.
- Перетаскивание устройств и автокомпоновка — в режиме «Редактировать расстановку», чтобы случайно ничего не сдвинуть.
- Пустое состояние (устройств нет): подсказка и кнопка «Найти устройства».

### Сценарии

- Слева список всех сценариев: название, условие (иконка приложения, «в фокусе» или «запущен»), в каких группах сейчас играет.
- Справа редактор на одной странице:
    - **Когда** — выбор из запущенных сейчас приложений с иконками или обзор exe; «в фокусе» или «запущен».
    - **Что** — сегменты Эффект / Сцена / Экран / Музыка / Игра / Встроенный, ниже настройки типа; все эффекты — плитками с картинками.
    - **Живое превью** сценария, даже если он сейчас не активен.
    - **Группы** — чипы; новый сценарий встаёт в группе над «По умолчанию».
- Тип «Сцена» открывает тот же холст сцены со слоями эффектов и их границами.

### Устройства

- Поиск и подключение, статус связи, возможности устройства, раскладка клавиатуры.
- Панель диагностики по каждому устройству.

### Настройки

- Частота кадров (20/30/60), длительность плавного перехода.
- Задержка снятия фокусного сценария: по умолчанию 2 с.
- Автозапуск с Windows, сворачивание в трей при закрытии.

### Трей

- «Выключить всю подсветку» / «Включить», «Открыть», «Выход».
- Двойной клик открывает окно.

## Дизайн-система

В интерфейсе нет ни одного стандартного элемента WPF или Windows в стандартном виде: каждый элемент — компонент из нашего набора на общих токенах.

### Токены

Палитра стекла (`Themes/Glass.xaml`) и токены размеров (`Themes/Tokens.xaml`); тема одна — тёмная, как в LedHub. Тонировку, карточки, блик и слой содержимого перекрашивает `GlassTheme` по настройкам «Стекла». В разметке нет жёстко заданных цветов и чисел, только ссылки на токены.

- Цвета: фон, поверхность, акцент, текст, состояния.
- Радиусы скругления, отступы по сетке 4/8 px.
- Шрифты и размеры.
- Длительности и кривые анимаций.
- Тени и обводки.

### Чем заменяем стандартные элементы

| Стандартный | Наш компонент |
| --- | --- |
| ComboBox (селект) | Сегменты до 4–5 вариантов; плитки с картинками для эффектов; выпадающая панель-карточка с поиском для длинных списков (приложения, exe) |
| CheckBox | Переключатель-тумблер или чип |
| RadioButton | Сегменты |
| Slider | Свой ползунок с подписью значения и цветной заливкой |
| TextBox | Своё поле с подсказкой внутри и подписью над ним |
| Button | Accent / Ghost / Danger / иконка |
| ScrollBar | Тонкий скрываемый скролл |
| ContextMenu, ToolTip | Свои всплывающие карточки, в том числе меню трея — окно WPF, а не системное меню |
| MessageBox, диалоги | Модальная карточка поверх окна |
| Заголовок окна | Своя рамка (WindowChrome) на системном стекле, кнопки окна системные; разделы — в левом меню |
| Выбор цвета | Свой круг или палитра |

### Как держим согласованность

- Новый экран собирается только из стилей `Styles/*.xaml`. Нужен новый элемент — сначала он становится стилем.
- Fluent-тему WPF (`ThemeMode`) не используем: стекло включается напрямую через DWM, как в LedHub.

## Этапы

Каждый этап заканчивается рабочим, собирающимся приложением.

0. **Основа и дизайн-система.** Конфиг с версией, Mica, токены, все компоненты из таблицы замен, витрина, свой заголовок окна с 4 вкладками, трей со своим меню. Результат: пустое приложение в трее и витрина.
1. **Устройства.** Перенос драйверов, поиск и подключение, почтовые ящики вывода, панель диагностики. Результат: устройства видны, им можно задать один цвет.
2. **Цикл кадров и эффекты.** Перенос галереи эффектов, превью на плитках тем же кодом, что и устройства; живые цвета на сцене. Результат: эффекты на всех устройствах, плавно, видно время кадров.
3. **Группы.** Группы на сцене (рамка, Ctrl+клик, обводка цветом, боковая панель), сценарий «По умолчанию». Результат: разные эффекты на разных группах.
4. **Сценарии.** Слежение за приложениями, вкладка «Сценарии», приоритеты перетаскиванием, плавные переходы, задержка для фокусных сценариев. Результат: главная новая функция работает.
5. **Сцена как содержимое.** Режим редактирования расстановки, автокомпоновка, проекция, слои с границами. Результат: сценарий может быть сценой.
6. **Экран и музыка.** Захват экрана, звук и микрофон, режимы спектра и ритма. Результат: сценарий может быть экраном или музыкой.
7. **Игры.** GSI для Dota 2 и CS2, полоски здоровья и маны на клавиатуре, «Другие игры». Результат: сценарий может быть игрой.
8. **Завершение переезда.** Встроенные эффекты устройств, импорт настроек из старого `%AppData%\LedHub\config.json`. Результат: старый LedHub больше не нужен.

## Открытые вопросы

- Нужно ли меню трея «Закрепить сценарий» — вручную включить сценарий в обход приоритетов?
- Нужен ли временный сигнал: коротко мигнуть при уведомлении и вернуть предыдущий сценарий?
