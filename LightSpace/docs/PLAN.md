# План Light Space

Light Space — приложение на .NET 10 + WPF в трее: у каждого устройства своя подсветка и яркость, наборы настроек сохраняются профилями и переключаются из трея.

Документ описывает состояние на ноябрь 2026. Исходный замысел — сценарии, которые сами переключаются по запущенным приложениям, — отложен: сценарии убраны вместе со слежением за приложениями (условия «запущен» / «в фокусе», приоритеты, переходы), их место заняли профили. Что из замысла осталось несделанным — в разделе «Что дальше».

## Решения

| Вопрос | Решение |
| --- | --- |
| Стек | .NET 10 + WPF |
| Подход | Новый проект |
| Работа в фоне | Один процесс с иконкой в трее, подсветка работает при закрытом окне |
| Что играет | У каждого устройства своё содержимое и яркость. Сцена применённого профиля играет один эффект сразу на нескольких устройствах вместо их подсветки |
| Наборы подсветки | Профили, переключаемые вручную (в окне и в трее); автоматического выбора по приложениям нет |
| Новые устройства | Драйверы внутри проекта |
| Тесты и CI | Юнит-тесты (`LightSpace.Tests`): миграции конфига, байты команд устройств, питание, профили, сцена, Robobloq, главная модель окна, загрузка XAML. Тесты гоняются только в релизном workflow; остальное — вручную через журнал устройств |
| Распространение | Версия в `LightSpace.App.csproj`, релиз по тегу `v*` через GitHub Actions: два exe — маленький под .NET 10 Desktop Runtime и самодостаточный сжатый. Приложение при запуске смотрит последний релиз на GitHub |
| Оформление | Тёмное тонированное стекло (Acrylic или Mica) под всем окном, свои компоненты на общих токенах; стандартных элементов в стандартном виде нет |

## Модель данных

Конфиг (`AppConfig`, версия 5). Прежние группы, «Вся сцена» со слоями и расстановка устройств убраны; миграция 4 → 5 переносит содержимое и яркость групп в подсветку их устройств, содержимое «Сцена» становится эффектом.

| Сущность | Что хранит |
| --- | --- |
| Устройство | Драйвер, возможности (адресное или нет, сколько светодиодов, как часто принимает кадры, есть ли встроенные эффекты) |
| Подсветка устройства (`DeviceLighting`) | Содержимое и яркость одного устройства; у каждого известного устройства ровно одна запись |
| Сцена (`SceneConfig`) | Эффект с настройками, режим (по пространству или синхронно), направление (слева направо, справа налево, сверху вниз, снизу вверх, из центра), яркость и устройства с местом на холсте: середина, размер, поворот |
| Играющая сцена (`Scene`) | Копия сцены последнего применённого профиля; null — сцены нет |
| Монитор (`Monitors`) | Поворот монитора, привязанная к нему лента и её раскладка; у ленты не больше одного монитора |
| Профиль (`Profiles`) | Название, копия `DeviceLighting` и своя сцена. Применение возвращает устройствам из профиля яркость и содержимое, остальные устройства не трогает, и включает сцену профиля вместо прежней |
| Общая яркость (`MasterBrightness`) | 0–100 %, умножается на яркость каждого устройства и сцены в снимке кадров |
| Содержимое | Одно из: эффект из галереи, встроенный эффект устройства, экран, музыка, игра (Dota 2, CS2, другие). Игра в интерфейсе не выбирается |

## Архитектура

Один поток кадров на всё приложение, у каждого устройства свой вывод, никаких общих изменяемых данных между потоками.

### Проекты

| Проект | Что в нём |
| --- | --- |
| LightSpace.Core | Цвета, геометрия сцены, модели конфигурации |
| LightSpace.Devices | Драйверы: BLE (ELK), Robobloq, Royal Kludge S98, Govee, Magic Home, Serial, WLED, OpenRGB, Tuya |
| LightSpace.Engine | Поиск и подключение устройств, цикл кадров, эффекты, вывод на устройства, источники (экран, звук, GSI игр) |
| LightSpace.App | WPF: окно, трей, страницы, компоненты дизайн-системы |
| LightSpace.Tests | Юнит-тесты |

### Потоки

1. **Поток кадров.** Один на приложение, кадр раз в 50 мс. Каждый кадр берёт неизменяемый снимок настроек и рендерит содержимое каждого устройства вне сцены и эффект сцены с общими часами для всех её устройств. Плавных переходов между содержимым нет.
2. **Вывод на устройство.** У каждого устройства почтовый ящик на один кадр: новый кадр заменяет неотправленный, поэтому медленный BLE не тормозит клавиатуру. Здесь же сглаживание клавиатуры и ограничение частоты (`MinFrameInterval`).
3. **Источники данных.** GSI-сервер игр, захват экрана и захват звука публикуют своё последнее состояние, рендер его только читает.
4. **UI.** Меняет конфигурацию — движок получает новый снимок. Обратно получает живые цвета устройств не чаще раза в 30 мс и только пока окно видно.

### Вывод и переподключение

- Неизменившийся кадр устройству повторно не отправляется.
- Итоговая яркость 0 (яркость устройства или общая) гасит устройство чёрным кадром — и эффект приложения, и встроенный эффект. Когда яркость возвращается, встроенный эффект запускается после сброса.
- Встроенный эффект ELK и Robobloq при смене только яркости не перезапускается: уходит одна команда яркости.
- После сброса ELK перед запуском встроенного эффекта выдерживается пауза; BLE-ленты после подключения сначала получают команду включения. Скорость встроенных эффектов ELK 0–100 % передаётся байтом не выше 0x74: на большей скорости MELK-OA21 останавливает часть эффектов.
- Не дошедшие включение, выключение и запуск встроенного эффекта повторяются через 5 с.
- Известные устройства, которых нет на связи, ищутся сами с нарастающей паузой (15 с → 5 мин), после пробуждения компьютера — сразу. Устройство, до которого команды не доходят дольше 30 с, переподключается.

### Пространство

У каждого светодиода и клавиши есть координаты в пространстве устройства, эффект — функция «цвет(x, y, время)». На этом работают экран и полоски здоровья и маны на клавиатуре (здоровье — верхняя половина клавиатуры, мана/броня — нижняя).

В сцене «по пространству» светодиоды устройства переносятся на общий холст шириной 1 и высотой 0,6 по месту, размеру и повороту устройства, поэтому один эффект переходит с устройства на устройство. В синхронной сцене каждое устройство остаётся в своём пространстве и играет эффект целиком. В обоих режимах пространство поворачивается так, чтобы эффект шёл в направлении сцены (`SceneSpace`).

### Конфиг и диагностика

- JSON в `%AppData%\LightSpace\config.json` с полем `Version` и миграциями при загрузке.
- Скрытый «Журнал устройств» в настройках (7 щелчков по заголовку): поиск, подключение и каждая команда, ушедшая на устройство.
- Счётчики вывода на странице «Устройства».
- Журнал приложения — `%AppData%\LightSpace\log.txt`: дата и время у каждой строки, отметки запуска и выхода с версией, необработанные ошибки. Если после «запуск» нет «выход», приложение упало.

## UX/UI: карта экранов

Слева меню: «Устройства», «Мониторы», «Профили», под ними список найденных устройств (каждое открывает свою страницу), внизу «Настройки». Меню сворачивается до значков. Окно открывается на «Устройствах».

### Устройства

- Поиск по Bluetooth, Wi-Fi и USB, пустое состояние с кнопкой «Найти устройства».
- По каждому устройству: протокол и адрес, выключатель питания, кнопка «Настроить подсветку», возможности (тип, адресные светодиоды, частота кадров, встроенные эффекты), раскладка клавиатуры, локальный ключ Tuya.
- Счётчики вывода: отправлено и пропущено кадров, последняя отправка и ошибка, время расчёта кадра на все устройства.
- «Забыть устройство».

### Страница устройства

- В шапке значок в меню, название, статус и выключатель питания.
- Вкладка «Эффект»: сверху плитки встроенных эффектов устройства, ниже эффекты приложения. Варианты одного эффекта — пресеты.
- Также «Музыка» и, у ленты за монитором, «Экран». Ленту за монитором можно выбрать прямо здесь.
- Настройки эффекта в выезжающей панели справа. У неподключённого устройства настроек нет.
- Устройство, которое играло «Игру» (или «Экран» у ленты, которую сняли с монитора), при запуске переходит на «Эффект».
- Устройство, которое играет сцену профиля, показывает плашку «Устройство играет сцену профиля» с кнопкой «Убрать из сцены»: оно возвращается к своей подсветке, сцена играет дальше без него, сцена в профиле не меняется.

### Мониторы

- Привязка ленты к монитору и ориентация монитора.
- Раскладка ленты: вид спереди или сзади, число светодиодов по сторонам, угол начала и направление ленты.

### Профили

- «Сохранить текущую подсветку» создаёт профиль. У профиля есть «Применить», «Записать текущую подсветку» и «Удалить», список устройств с их содержимым и отметка «Сейчас играет этот профиль».
- У каждого устройства в профиле — яркость, «Изменить эффект» (галерея эффектов с настройками правит профиль, не трогая того, что играет сейчас) и «Убрать из профиля».
- «Собрать сцену» ставит подключённые и известные устройства профиля в ряд на холсте с эффектом «Радуга» и открывает редактор сцены; у профиля со сценой — «Настроить сцену» и «Удалить сцену».
- Редактор сцены: состав (переключатель у каждого устройства профиля), холст с живым превью (устройство перетаскивают мышью, колесо или ползунок меняют размер, «Повернуть» — на четверть оборота), режим «По пространству» / «Синхронно», направление, яркость сцены и галерея эффектов. Правки сцены — правки профиля: на устройствах сцена включится, когда профиль применят.

### Настройки

- Внешний вид: прозрачное стекло (Acrylic) или матовое (Mica), готовые варианты стекла и тонкая настройка.
- Подсветка: общий выключатель и общая яркость.
- Запуск: автозапуск с Windows (сразу в трей).
- О приложении, скрытый «Журнал устройств».
- Частоты кадров и длительности переходов в настройках нет: кадр фиксирован, 50 мс.

### Окно и трей

- Закрытие окна завершает приложение, сворачивание прячет его в трей.
- Меню трея — своё окно WPF: выключатель подсветки, общая яркость, профили, «Открыть Light Space», «Выход».
- Подсказка значка в трее показывает, сколько устройств без связи.

## Дизайн-система

В интерфейсе нет ни одного стандартного элемента WPF или Windows в стандартном виде: каждый элемент — компонент из нашего набора на общих токенах.

### Токены

Палитра стекла (`Themes/Glass.xaml`) и токены размеров (`Themes/Tokens.xaml`); тема одна — тёмная. Тонировку, карточки, блик и слой содержимого перекрашивает `GlassTheme` по настройкам «Стекла». В разметке нет жёстко заданных цветов и чисел, только ссылки на токены.

- Цвета: фон, поверхность, акцент, текст, состояния.
- Радиусы скругления, отступы по сетке 4/8 px.
- Шрифты и размеры.
- Длительности и кривые анимаций.
- Тени и обводки.

### Чем заменяем стандартные элементы

| Стандартный | Наш компонент |
| --- | --- |
| ComboBox (селект) | Сегменты до 4–5 вариантов; плитки с картинками для эффектов; выпадающая панель-карточка с поиском для длинных списков (приложения, exe) |
| CheckBox | Переключатель-тумблер или чип |
| RadioButton | Сегменты |
| Slider | Свой ползунок с подписью значения и цветной заливкой |
| TextBox | Своё поле с подсказкой внутри и подписью над ним |
| Button | Accent / Ghost / Danger / иконка |
| ScrollBar | Тонкий скрываемый скролл |
| ContextMenu, ToolTip | Свои всплывающие карточки, в том числе меню трея — окно WPF, а не системное меню |
| MessageBox, диалоги | Модальная карточка поверх окна |
| Заголовок окна | Своя рамка (WindowChrome) на системном стекле, кнопки окна системные; разделы — в левом меню |
| Выбор цвета | Свой круг или палитра |

### Как держим согласованность

- Новый экран собирается только из стилей `Styles/*.xaml`. Нужен новый элемент — сначала он становится стилем.
- Fluent-тему WPF (`ThemeMode`) не используем: стекло включается напрямую через DWM.

## Что дальше

Код есть, но в интерфейс не выведен:

- **Содержимое «Игра».** Рендер, GSI-сервер для Dota 2 и CS2 и `GameEditor` есть, но в списке типов (`ContentKindOption.All`) его нет.
- **Неподключённые редакторы.** `BuiltinEditor.xaml`, `ScreenEditor.xaml` и `GameEditor.xaml` нигде не используются.

Не проверено на железе:

- WLED (mDNS + DDP), OpenRGB (SDK-сервер на localhost:6742, протокол версии 3), Tuya 3.4 / 3.5 (сессионный ключ, HMAC-SHA256 / AES-GCM). Проверены только тестами на байты протокола.

Отложено вместе со сценариями:

- Автоматическое переключение по запущенным приложениям или окну в фокусе, приоритеты, плавные переходы, задержка снятия фокусного сценария.
- Настройки частоты кадров и длительности перехода.

## Открытые вопросы

- Возвращать ли сценарии поверх профилей: профиль включается сам, когда запущено приложение?
- Выводить ли в интерфейс игры или убрать этот код вместе с неподключёнными редакторами?
- Нужна ли сцене вне профилей своя страница, чтобы собирать её прямо на устройствах, без применения профиля?
- Нужен ли временный сигнал: коротко мигнуть при уведомлении и вернуть предыдущую подсветку?
